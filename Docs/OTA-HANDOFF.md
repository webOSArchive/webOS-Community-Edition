# OTA hand-off: CE 3.1.0 → 3.2.0 (Path A)

State at the end of 2026-11-21 (evening), everything pushed; picked up again **Monday
2026-11-23 with the 600120 bake**. The plan and every finding are in
[OTA-PLAN.md](OTA-PLAN.md): §2.0 (the measurement), §2.0a to §2.0m (every run on a device,
in order), §2.2 (`ce-ota-finish`). This page is where it stands and what to do next. It
replaces the hand-off of 2026-11-20 (600114).

## In one paragraph

An unsigned payload that turns a 3.1.0 rootfs (600070) into 3.2.0 is generated by a tool
and **goes through the stock update ramdisk unaided** on both test TouchPads: clean,
lived-in (Atlas, QupZilla and its Qt5 stack, Videos, Media TLS, Chat Enabler), with an
Exchange mail account, and with a third-party language pack. `ce-ota-finish` finishes every
run by itself on the first boot. A Full Erase after an update and a fresh flash both come up
right. A failure inside the ramdisk recovers on a retry, and the bricked state after four
failures was recovered without the Doctor. **The device side is done, and so is the
client:** OTA Ready 3.0.0 from App Museum II takes a 3.1.0 TouchPad to 3.2.0 from System
Updates' Install Now, with a signed manifest from swupdate.webosarchive.org, and a
per-release device filter on the server decides who is offered it. Proven on two devices
in production. The client stays in the Museum (not baked into 3.2.0, decided).
**Not done:** the release build 600120 (Monday), AT&T. **600119 is the latest image; two changes wait for 600120 (below).**

## The armed flash, by hand

1. The device must be at 600070, **first use finished** (`/var/luna/preferences/ran-first-use`)
   and no `ce-*` job running (`initctl list | grep ") ce-"`; `woce-backupd` always runs).
2. Save a file list of `/media/internal` and run the pre-flight (`--delta`). Go on only on
   "may be applied".
3. `novacom put` the ipk to `/media/internal/ce-ota/`, check its md5.
4. Session files in `/var/lib/software/SessionFiles/`: `update_list.txt` (the device path),
   `install_list.txt` (the same under `/rootfs`), and `urls`: **a header line, a line that
   is exactly `version=1`, then five lines for each package.** It is not a list of URLs.
5. `/usr/bin/PmUpdater -v` (validates without installing). `update_status.txt` must stay
   empty.
6. `echo 1 > /var/lib/software/updating`, then
   `/usr/share/ota-scripts/make-update-uimage </dev/null >/tmp/mu.out 2>&1`,
   check `/boot/uImage -> update-uimage`, `killall fbprogress`, reboot.
7. About 100 seconds in the ramdisk, then the new image. `ce-ota-finish` needs one to two
   minutes after boot. Read `/var/log/ce-ota-finish.log` (last line "finished and
   verified"), `/var/log/ota.log.gz`, `/var/log/reports/librdx/`.
8. `device-check.py` against the new JAR; compare the file list of `/media/internal`
   (differences under `.palm` are cryptofs's own storage).

**When it fails inside the ramdisk** (§2.0m): it retries after a reboot, about every 37 s;
after the fourth failure it deletes `/boot/uImage` and the bootloader shows "!" and
www.palm.com/ROM (novacom: `topaz-bootie`). Recovery without the Doctor:
`novacom -d <id> boot mem:// < uImage-2.6.35-palm-tenderloin` (from the old image's rootfs
`/boot/`), then `mount -o remount,rw /boot; ln -sf uImage-2.6.35-palm-tenderloin
/boot/uImage; rm /boot/update-uimage`, reboot. Stuck in the ramdisk with Linux up:
`../webos-update-exploration/OTA-UPDATE-GUIDE.md`, "Device Stuck in OTA Ramdisk".

novacom: start device commands with `novacom` (the allow rule matches that), pass scripts on
stdin (`novacom -d <id> run file://bin/sh <<EOF`); `-c` is not supported; the device has no
`stat` or `sha256sum`; `ipkg compare_versions` exits 1 for true; luna method names cannot
contain a hyphen; db8 queries from the shell need `-a com.palm.app.email` (or the owning app).

### The client stays in the Museum (decided 2026-11-21)

Every 3.2.0 user, however they got there, should install OTA Ready (or keep it installed)
to receive future updates. If they uninstalled it, or never had it, reinstalling it is all
it takes.
- **Updated by OTA:** the client survives the update (the payload replaces only the files it
  names), so the device keeps getting offers while OTA Ready stays installed.
- **Uninstalled:** the prerm removes the whole client (daemon, job, helper, bridge) and puts
  the stock System Updates back (keeping 3.2.0's own appinfo). No offers until reinstalled.
- **Flashed with the 3.2.0 Doctor:** no client until OTA Ready is installed, as on 3.1.0.
- **Full Erase:** wipes the app and its bridge (cryptofs) but probably leaves the rootfs half;
  reinstall OTA Ready even if it looks installed (untested).
- Reinstalling on 3.2.0 is safe: the postinst saves 3.2.0's own System Updates as the stock
  copy.
- An offer still needs a release that starts at the device's build (600070 -> 600120;
  600119 -> 600120 for testers; AT&T from 600071, not built) and an entry in
  `releases.json` that admits the device.

Why not baked (the risks weighed): the baked and Museum copies of the bridge service would
both be registered after an OTA, and ls-hubd drops both (the device could not install);
a baked client can only be fixed by an OTA, which a broken client cannot deliver (the
Museum package steps aside for a baked one); every 3.2.0 device would contact the server
unasked; and the rootfs-registered paths are untested. If it is ever baked: fix the double
registration (ce-ota-finish removes the Museum registration, or another service name),
let a newer Museum version replace the baked one, and test before the bake.

## Things that will bite

- **Never rebuild a JAR for a mark that was shared.** 600105 went to other developers.
  600108 to 600119 have not left this machine.
- **`ce-ota-finish` knows no version.** It compares the image it runs in with the origin
  lists. A new origin image means a new list (`make-payload.py finish-list`), nothing else.
- **A flashed device does nothing in that job**: no `ran-first-use` at boot means it writes
  both flags and exits. Keep that property.
- **Installs go through `com.palm.appinstaller/installNoVerify`**, never plain
  `app-install`/`ipkg`: only LunaSysMgr's installer registers a package's services. The
  first-boot preload pass is plain ipkg, which is why `ce-register-cryptofs-services` exists.
- **A flashed device is not the rootfs tar.** The Doctor adds `hp.tar`'s four customization
  ipks; `make-payload.py` reads hp.tar's staged media from the new JAR. `hp.tar` is identical
  in 600070 and 600119; check that again for any new pair.
- **File names with spaces.** hp.tar's ringtones have them; shell loops over `find` output
  must split on newlines only (§2.0l).
- **The NVRAM write is real.** `trenchcoat` rewrites the whole 4 MB partition, tokens
  included. The job saves it to `/var/ce-ota-nvram-backup.img` first.
- **A device test that reads files is not a test that the thing works.** The launcher layout
  and Photos' service both passed file checks on every 3.2.0 image and were broken.
  `ce-test-full.sh` now checks the dock save, the Settings page and the service on the bus.
- **The OTA client, server and keys live in `../webos-update-exploration`.** Its
  `OTA-3.1.0.md` is the reference. `Docs/OTA-STRATEGY.md` here is stale.
- **The user edits `releases.json` on the host** as testers sign up. The repo copy is
  `{"releases": []}`: pull the host's version before committing a change to it, or a push
  (git-to-deploy) withdraws every tester's offer.
- **OTAs start at 3.1.0.** 3.0.5 devices get the Doctor; OTA Ready says "Not eligible" there.
- **The client's checks run on the device and the server cannot switch them off:**
  TouchPad hardware, signature, from-build, pre-flight file, stock kernel, first use, space.
  The server's filter is rollout policy only.
- **busybox sh arithmetic is 32-bit and an error exits the script.** Space math is in KB.
